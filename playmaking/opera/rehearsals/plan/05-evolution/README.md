- **`Orders`:** Assign each concrete move for this Plan to a Persona, Position, or role. Putting the `00:00:00` relay, `15s` USB scan, and hot-mic bleed in [place-studio.md](../02-company/place-studio.md) and [process-final-broadcast.md](../02-company/process-final-broadcast.md) kept studio physics identical across runs while `Implementation` carried approach-specific gates ([01](../04-runs/01-read-live-a.md)–[04](../04-runs/04-hold-for-recording-b.md)).
- **`Targets`:** List observable results. Start each at `[ ]` (open), then record its verdict from what happens: `[x]` done, `[F]` attempted and missed, `[W]` dropped or overtaken, `[-]` cut as moot or inapplicable, or leave `[ ]` open to carry forward if the scene ends before the target is settled. *(Authoring note: shared outcome-level targets—such as Target 3 accepting recorded voice or spoken attribution—let competing Plans close `[x]` on the same broadcast; if an author wants a contingency switch to register `[W]`, include a target specific to the overtaken approach.)*
