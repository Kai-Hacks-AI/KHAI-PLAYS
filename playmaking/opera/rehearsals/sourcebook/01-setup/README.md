# SCORE rehearsal plan — Sourcebook

## Question

Does the Sourcebook help an independent reviewer trace a Playwright’s design decision and a Director’s staging decision from intent to source, limits, and implementation?

## Set up

- Use the fixed [reviewer brief](../02-company/reviewer-brief.md) and one packet per run.
- Condition A gets [plain source notes](../02-company/plain-notes.md). Condition B gets a [Sourcebook](../02-company/sourcebook.md) using the [Opera reference](../../../references/sourcebook.md).
- Both packets use the same eight bullets verbatim, in the same order, with identical links. Condition B adds only the four chapter headings and a different title. The reviewer receives only the brief and their assigned packet. Keep this protocol, the other packet, and the scoring key out of the reviewer’s context.
- Use the same model and instructions, time or token budget, and access to linked sources. Use the pinned Pitch draft and rehearsal evidence in the packets. The experiment can run while the Pitch PR is open. Record any inaccessible source for each run and use the same access conditions in both arms.
- Record the rehearsal commit and run settings before execution. Use eight fresh reviewer contexts, four per condition, in the order A, B, B, A, B, A, A, B. Save the original responses before scoring. If a run fails to produce a response, log the failure and rerun that slot in a fresh context.

## Predeclared scoring key

Score each item as 1 when present and supported by a cited file or section, otherwise 0. Score both claims independently for a maximum of 8 per run.

| Check | Playwright decision on the Tenors | Director decision about the shoe |
| --- | --- | --- |
| Purpose | Identifies the nine as starting registers for authoring a Pitch. | Explains the proposed shift in audience attention toward the oversized shoe at the child’s eye level. |
| Evidence | Names both the legacy KHAI defaults and the rasa analysis, with each source’s role. | Locates the rehearsal record and identifies dry comedy and quiet wonder as the tested Tenors. |
| Limits | Treats the correspondence with Navarasa as a parallel and leaves historical derivation unconfirmed. | Identifies one shared Pitch per run and leaves the mixed-Pitch example at proposal status. |
| Encoding | Points to the standard Tenors in `pitch-defaults.md` and gives wording supportable by the evidence. | Points to the mixed-Pitch example in `pitch-defaults.md` and gives wording that preserves the Piece cue as a proposal. |

Give unlabeled responses to the scorer in a mixed order where feasible. Record any case where the response reveals its condition. Record supporting excerpts, scoring disagreements, unsupported claims of derivation or rehearsal evidence, and source-access problems. Report individual scores and the median and range per condition. With this small sample, report observed differences and their limits. Consider the format promising if it improves traceability on both tasks without increasing unsupported claims. Record mixed results and whether individual chapter labels helped or caused confusion.
