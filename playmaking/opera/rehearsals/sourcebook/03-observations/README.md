## 5. Observed Differences, Chapter-Label Effects & Sample Limits

- **Evaluation against the predeclared decision rule ([01-setup/README.md](../01-setup/README.md#L26)):** The plan defines the Sourcebook format as *"promising if it improves traceability on both tasks without increasing unsupported claims."* While Condition B produced **`0`** unsupported claims, it **tied Condition A at the `8/8` ceiling** on the primary rubric (`8.0` median, `8–8` range in both arms) and trailed slightly on the strict `D2-Encoding` sensitivity check (`7.5` vs. `8.0` median). Adding the four chapter headings alone therefore **did not measurably improve reviewer traceability** over plain source notes in this configuration.
- **Whether individual chapter labels helped or caused confusion:**
  - **`Line of Work`, `Origin`, and `Restrictions` helped structure citation provenance without inflation:** `08-run-b4` (`#L14`) used `#origin` directly as a section anchor when attributing the offline Zarrilli citation, and all four Condition B runs cleanly separated confirmed `ChBrain/khai` provenance from unconfirmed derivation and unrehearsed multi-object scope.
  - **`Encoding` showed mild ambiguity when mixing an adopted rule with a tentative illustration:** [references/sourcebook.md](../../../references/sourcebook.md#L19-L21) defines `Encoding` as *"where each supported idea becomes a choice someone can use."* Placing an adopted default (`#standard-tenors`) and an unrehearsed proposal (`#several-pitches-in-one-scene`, *"This is proposed staging guidance"*) together under `## Encoding` did not prevent two Condition B runs (`03-run-b2` `#L43-L44`, `05-run-b3` `#L59`) from treating `05-evolution/README.md`’s `khai-director/SKILL.md` (`L9`) rule as the actionable staging cue while summarizing the four-scope block only collectively.
  - **Bundling two decisions inside one four-chapter packet interleaved unrelated bullets:** Each chapter in [sourcebook.md](../02-company/sourcebook.md#L3-L21) paired `[Tenors bullet, Shoe bullet]`, splitting each decision’s chain across four headings (`L5/L10/L15/L20` vs. `L6/L11/L16/L21`) that every reviewer had to untangle back into per-decision chains.
- **Ceiling and design limits (`n = 4` per arm):**
  1. Because [plain-notes.md](../02-company/plain-notes.md) used the **exact same eight bullets in `Line of Work → Origin → Restrictions → Encoding` order** ([01-setup/README.md](../01-setup/README.md#L11)), Condition A inherited the Sourcebook’s underlying warrant completeness and sequence without headings—isolating *heading labels at read time* rather than *warrant completeness at write time*.
  2. All five accessible GitHub snapshots were self-explanatory Markdown documents ([pitch-defaults.md](../../../skills/khai-playwright/references/pitch-defaults.md), [pitch/03-observations/README.md](../../pitch/03-observations/README.md), [mixed-pitch/03-observations/README.md](../../mixed-pitch/03-observations/README.md), [mixed-pitch/05-evolution/README.md](../../mixed-pitch/05-evolution/README.md), and `ChBrain/khai` `defaults/pitch.md`), enabling attentive reviewers in both arms to verify every link directly and saturate the 8-point scale at `n = 4`.
